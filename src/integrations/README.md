# Supabase и запись

## Каталог

`supabase.ts` читает только VITE_SUPABASE_URL и VITE_SUPABASE_PUBLISHABLE_KEY.
Скопируйте `.env.example` в `.env.local` для локальной проверки. В Vercel эти
переменные должны быть доступны при сборке; после изменения нужен redeploy.
Секретные/service_role ключи нельзя помещать в VITE_*.

Клиент выполняет только SELECT публичного каталога:
- services: id int8, name, description, duration_minutes int4, price int4 (рубли).
- barbers: id int8, name, role, specialty, image.

Используются существующие публичные SELECT-политики RLS. SQL/политики не меняются.
ID нормализуются в строки для формы. Небезопасные JS integer ID отклоняются.
Пустые таблицы показывают пустое состояние, ошибки — сообщение и повторную загрузку.
Демонстрационные данные сохранены в content.ts, но не маскируют ошибки базы.
Изображения barbers.image используют прежний контракт: идентификатор локального
изображения, например master-1 → /images/master-1.jpg.

## Форма сейчас

Выбор мастера, услуги, даты и времени; длительность берётся из services.
Время салона — Europe/Moscow, UTC+03:00, часы 10:00–22:00.
Формируются starts_at/ends_at в ISO UTC. Прошлое время и выход за часы работы
отклоняются. Это предварительный расчёт, а не проверка занятости.
Нет запросов к bookings, сбора имени/телефона, localStorage или отправки формы.
Кнопка подтверждения отключена; интерфейс не сообщает об успешной записи.

## Предлагаемый серверный API (ещё не реализован)

1. Edge Function или отдельный backend: POST /api/bookings. Только HTTPS,
   allowlist Origin, ограничение размера тела, rate limit и CAPTCHA/защита от ботов.
   При cookie-авторизации также CSRF. Не логировать имя/телефон или полное тело.
2. Вход: barber_id, service_id, starts_at (ISO с offset), client_name, client_phone.
   Проверить типы, допустимые длины, нормализовать телефон. Не принимать от клиента
   ends_at, duration, price, status. Проверить существование мастера/услуги и
   применимость услуги, если появится такая связь.
3. Сервер заново читает duration_minutes, вычисляет ends_at, проверяет будущее
   время, горизонт записи, рабочие часы, выходные/отпуска в Europe/Moscow.
   Статус задаёт сервер; сверить допустимые значения CHECK/enum в реальной базе.
4. Серверный endpoint доступности возвращает только свободные интервалы без
   SELECT записей/имён/телефонов в браузере. Доступность предварительная.
5. Вставка должна быть атомарной. Сохранить существующее bookings_no_overlap;
   проверить его определение и точный статус подтверждённых записей. Если статус
   confirmed входит в предикат ограничения, вставлять confirmed в транзакции.
   Предварительная SELECT-проверка не предотвращает гонку: PostgreSQL exclusion
   constraint — окончательная защита. SQLSTATE 23P01 → HTTP 409 «Время уже занято».
   При переходе pending → confirmed обрабатывать тот же конфликт в транзакции.
   ends_at > starts_at и полуоткрытые [start,end) интервалы должны быть проверены
   по фактической схеме до запуска; не пересоздавать ограничение вслепую.
6. Идемпотентность через серверный ключ запроса и UNIQUE ограничение/отдельное
   хранилище: повторный запрос не должен создавать вторую запись.
7. Service-role/secret только в серверном окружении. Для bookings не добавлять
   публичные INSERT/SELECT политики; проверить существующие grants/RLS. Не
   предоставлять публичный SECURITY DEFINER RPC с произвольным доступом к PII.
8. Возвращать минимальный ответ без PII и данных других клиентов. Показывать
   успех только после подтверждённого COMMIT. Сетевой сбой не означает успех.
   Добавить правила хранения/удаления PII и ограничить доступ сотрудников.

## Проверка и ограничения

`npm run build` включает TypeScript (`tsc -b`) и production-сборку Vite.
Без параметров Supabase в среде Codex нельзя подтвердить реальные ответы,
содержимое таблиц, политики RLS, изображения и определение bookings_no_overlap.
Vercel-переменные автоматически в Codex не передаются. После deploy проверить
каталог на реальной базе. Серверная запись и выдача свободных слотов — следующий
этап; описанный API сейчас не развёрнут.
